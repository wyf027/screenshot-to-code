# 截图转代码：20 服务器 Codex CLI 与公开试用额度

状态：方案待用户确认；尚未实现或发布。日期：2026-10-26（Asia/Shanghai）。

## 用户已经确定的要求

- 修改的是 `screenshot-to-code-blue.vercel.app` 的截图转代码功能，作品集入口仍为 `wyf-ai-lab.netlify.app`。
- 所有人可以使用，不采用之前讨论的仅主人密码访问方案。
- 使用 20 服务器上自己的 Codex CLI，先找现有接口，没有就搭建。
- 每位访客每天 20,000 token，全站每天 200,000 token；输入加输出计费，达到额度后停止新生成。
- 不要求访客填写模型 API Key，不自动改用付费 API 或创建新密钥。

- 未找到可直接供此网站调用的公开 Codex HTTPS 生成接口。

- 用量在模型调用后报告；未找到可验证的每次请求硬性输出 token 上限。`features.rollout_budget` 是开发中的预算追踪功能，不能作为精确截断保证。
- 公开站当前在 Vercel，React/Vite 前端和 FastAPI 后端。现有 Netlify 账号已授权部署。
- 官方 App Server 文档明确将其现有认证限定于本地或开源应用，不支持用于托管服务。用户已知该区别并再次要求采用自己的 CLI。本方案记录技术可行性，不把它描述为官方支持的公共托管产品，也不绕过订阅平台的限额或认证。

## 访客体验

1. 打开页面即可获得签名访客标识，设置区域显示“公开试用”、每日额度和剩余额度。
2. 上传截图或输入需求，提交到网关。第一版保留文字、截图和修改生成代码，不开放视频生成及服务器资产工具。
3. 每次只生成一个方案，使用固定模型与推理档位，避免原来四个候选的四倍用量。
4. 排队和生成时显示真实任务状态；生成完成后显示代码和预览。第一版无需逐 token 流式展示。
5. 额度耗尽、排队满、worker 离线、CLI 登录失效、平台限流、取消和超时均有对应提示。
6. 刷新页面可以恢复当前任务。获取他人的任务结果必须失败。
7. 公开版不再显示必须配置模型 Key 的紫色提示。原有 BYOK 代码保留，不能因公开模式的失败而自动调用另一付费来源。

## 额度定义和边界

- 账期为北京时间日历日，调用开始时确定归属日；跨午夜的已开始调用仍计入开始日。
- `input_tokens + output_tokens` 为总用量，缓存输入和推理输出仅作明细，不重复加算。
- 无账号登录时，“每位访客”使用签名随机访客 ID 加可信来源 IP 的 HMAC 双重限制。清除浏览器缓存不能绕过同一 IP 的额度。
- 同一出口 IP 的不同访客共享 IP 限额；代理或更换网络可能绕过个人限制，因此全站限额仍是最后一道限制。页面说明匿名额度按浏览器及网络识别。
- 每个访客/IP 一次只能有一个未完成任务，全站模型调用并发为 1，排队最多 5 个。
- 提交与开跑均在持久化状态上检查个人/IP/全站已用量和预留量。预留、状态迁移、完成结算使用原子条件写，不能靠实例内存限流。
- 为任务预留最多 20,000 token，实际完成按真实用量结算，多余预留释放。剩余不足 6,000 token 不再接受生成，避免仅剩极小额度仍启动一次完整调用。界面显示“剩余额度不足以开启一次生成”，不伪称已用完。
- 超过任一日限额后，拒绝新的模型调用。已开始的一次调用可能导致实际累计超过限额；真实用量不截断、不隐藏。全站串行把这一偏差限制在一个在途模型调用范围内。
- 120 秒任务超时、输入大小和输出字符上限是额外保护，不能称为 token 硬上限。
- 没有用量报告的失败/中断记为“用量未知”，不记成零。该账期暂停后续生成并显示原因，避免未知消耗导致无限重试。
- 订阅平台自身的限制独立生效，网站额度不增加个人账号的可用订阅量。

## 网关和任务状态

使用 Netlify Functions 与 Blobs 强一致读取、ETag 条件写。发现后端不支持可靠的条件写时，停止发布，而不是降级成无原子保护的写入。

- 公开接口只接受应用约定的字段。访客不能提交模型名、工作目录、命令、工具、环境变量、任意后端 URL 或 CLI 参数。
- 可信 IP 取自 Netlify 平台 context，不信任客户端 `X-Forwarded-For`。
- 访客会话使用服务端签名，不以客户端提交的 ID 直接作为账本主键。
- 图片只允许有限体积/数量/尺寸的 PNG、JPEG、WebP data URL；不让服务器下载任意图片 URL。总请求体不超过 3 MiB，文字与历史有明确长度限制。
- worker 接口使用独立随机传输密钥；密钥仅存在于网关函数环境和服务器权限 0600 的配置文件中，不进入浏览器、源码、构建产物或日志。
- 任务状态：queued → running → completed / failed / cancelled / expired。领取使用唯一租约和原子状态迁移，运行中的任务永不再次领取执行。
- 心跳显示 worker 是否在线。租约失效的在途任务标为过期且用量未知，不自动重跑模型调用。
- 完成回传必须可幂等重试。worker 在本机受保护的 outbox 保存待回传结果，网络恢复后只重传结果，不再次调用模型。
- 请求 ID/任务 ID 用于状态跟踪，但访问结果还必须验证访客身份。
- 仅保存运行所需的截图、提示词和结果；完成任务最多保留 24 小时，定期清理。账本保存聚合用量，不包含原始 IP、提示词或图片。
- 浏览器来源允许列表只含实际部署地址及本地开发地址；CORS 仅为浏览器限制，不能代替服务端身份、配额和任务授权检查。

## 20 服务器 worker

- 独立用户 systemd 服务，例如 `screenshot-codex-worker.service`；主动连接网关，不监听公网端口。
- 调用本机官方 CLI，不提取或复制 ChatGPT OAuth 令牌。登录仍由 Codex 官方流程管理。
- 每任务新建临时会话，`ephemeral: true`，`environments: []`，`selectedCapabilityRoots: []`，`dynamicTools: []`。
- 禁用 shell、文件、网页搜索、浏览器、连接器、MCP、插件、记忆、hooks 和多代理能力；清理继承环境，禁用个人/项目指令加载。
- 需要验证个人配置中的 MCP 和插件不会因合并行为重新出现。发现工具启动、审批请求或未知执行事件立即终止任务。
- 模型初始建议 `gpt-6-luna`、low 推理，启动前确认该账号实际可用且支持图片。不得自动切换到更贵模型或其他认证方式。
- 输入仅是用户的截图、有限历史和生成代码说明；输出仅当作文本交给浏览器，worker 不运行生成代码。
- 只返回用户可见代码和状态，不回传模型内部推理、CLI 原始日志、账号信息或主机路径。
- CLI 退出、取消、超时均终止相关子进程；服务重启不得重复运行已经领取的任务。
- 新服务的资源限制、独立工作目录和状态目录与现有个人项目隔离。

## 前端集成和预览

- 增加网关模式适配器，将公开任务响应转换成现有 `variantCount`、`setCode`、`variantComplete` 等回调。
- 将取消连接抽象为仅需要 `close()` 的接口，保留原有 WebSocket 路径，避免把伪造对象强制断言为完整 WebSocket。
- 网关地址由 `VITE_CODEX_GATEWAY_URL` 配置；生产不依赖开发机 localhost。
- 自动解析代码围栏但不执行服务端代码。公开预览 iframe 必须与应用会话隔离；不同时授予脚本和同源权限。
- 如现有元素选取依赖 iframe 同源 DOM 访问，公开模式先禁用该选取功能并说明，避免预览代码读取访客令牌或调用主站接口。

## 验证和发布标准

1. 单元测试：并发预留不重复、每日边界、缓存/推理不重算、失败未知用量、取消、重复回调、过期租约和跨访客读取。
2. worker 协议测试：使用假 CLI 模拟所有状态，确保工具事件失败关闭、子进程被回收、没有隐式重跑。
3. 使用一张无敏感信息的截图跑真实 CLI 调用，核实输出和 token 统计。
4. 网关线上验证：未授权 worker 请求失败、低额度拒绝、worker 离线提示、CORS、隐私清理以及真实原子写行为。
5. 前端：构建和 lint，按仓库要求记录已有 baseline 问题；如改动 Python 才执行 Poetry pytest/pyright。
6. 浏览器端完整验证：截图提交 → 20 服务器 CLI → 代码返回 → 预览 → 额度变化；另外测试刷新恢复、取消、超额和另一个访客读结果失败。
7. 先建立预览部署验证，成功后更新现有 Vercel 生产站。提供最终可用地址和服务停用方法。
